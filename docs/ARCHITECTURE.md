# 기술 설계

기준: [PRD](../PRD.md). 화면은 별도 저장소다. API·업무 규칙·외부 연결을 한 코드베이스에서 분리한다.

## 구성

| 구성 | 선택과 역할 |
|---|---|
| HTTP API | FastAPI·Pydantic, 입력 계약·인증·응답·오류 |
| 업무 저장소 | SQLAlchemy·PostgreSQL, 사용자/Role/승인/실행/감사·대화 영속화 |
| 문서 검색 | PostgreSQL pgvector, 문서 원천 위치·권한·벡터 관리 |
| 관계 저장소 | Neo4j, 승인된 온톨로지 실체 및 관계 탐색 |
| 에이전트 | LangGraph, 해석 → 권한 → 계획/도구 → 검증 → 응답 상태 |
| 초기 모델 | Groq API, 환경변수 키와 설정된 모델 ID. TLS·프록시 신뢰 유지 |
| 후속 Local | Ollama 어댑터, 설치 시 동일 모델 계약 구현 |
| 장시간 처리 | 별도 작업 프로세스, 문서 처리·적재·재시도·상태 검사 |

## 인증과 권한

비밀번호는 Argon2id로 해시한다. 초기에는 무작위 opaque bearer 세션을 사용하고 DB에는 토큰 해시만 저장한다. 만료·로그아웃·사용자 비활성화를 확인한다. 최초 Admin은 서버 CLI로 생성하며 기본 비밀번호나 공개 가입 API는 두지 않는다.

Role은 허용 업무와 데이터 범위를 갖는다. 복수 Role은 허용 합집합이며 같은 Role의 업무/범위 쌍으로 평가해 서로 다른 Role의 범위를 잘못 결합하지 않는다. Admin 관리 권한과 일반 업무 권한을 구분한다. 모든 도구 호출에서 DB의 현재 Role을 읽으며 입력 문장이나 모델 출력은 권한을 부여하지 않는다.

## 승인·실행

승인 대상은 요청자·업무·원천 대상·확정된 매개변수·요청 식별자다. 승인/반려 이력을 영속 저장한다. 승인 후 실제 실행 전에는 요청자와 승인자의 현재 권한 및 원천 상태를 재확인한다. 초안은 승인 객체마다 하나만 생성 가능해야 한다. 초기 승인 기반은 상태 관리까지이며 실제 업무 도구 연결 전에는 승인됨을 실행 완료로 표시하지 않는다.

## 모델 계약과 에이전트

모델은 구조화된 의도·대상·누락 정보를 반환한다. Pydantic 스키마와 허용 업무 목록으로 검증한다. 자유 SQL/Cypher/URL이나 모델 생성 권한을 실행하지 않는다. 응답에 실제 제공자·모델 및 상태를 포함한다. 잘못된 JSON·비허용 업무·타임아웃·429·인증 오류는 명시적으로 처리하고 실패를 성공으로 바꾸지 않는다.

Groq는 `GROQ_API_KEY`를 환경변수에서만 읽는다. 고정 HTTPS 목적지를 사용하고 리다이렉트를 따르지 않는다. 키·원시 응답·인증 헤더는 로그에 남기지 않는다. 환경의 프록시와 CA 신뢰를 유지한다. 외부 전송 허용 범위를 검사하기 전에는 내부 업무 데이터나 대화 이력을 모델에 보내지 않는다.

## 감사와 대화

요청 ID·사용자·대화·단계·업무·판정·오류 코드·시간·제공자·모델을 저장한다. 민감 원문 대신 구조화된 최소 실행 메타데이터를 기본으로 한다. 대화 소유권을 검사하고 과거 실행의 데이터 접근 권한을 현재 권한으로 재검사한다. CoT 원문을 저장하지 않는다.

## 후속 설계 계약

온톨로지: 유형/실체 구분, 원천 키·매핑·버전·검토, 경로 조회, 참조 오류 격리.
RAG: 형식별 추출 범위, 표/페이지/시트, Chunk·임베딩 버전, 검색 전 권한, 삭제/갱신, 검색/컨텍스트/인용 지표.
재고: 최신 기준 시점, 안전재고·발주량 규칙, 기존 발주 확인, 내부 알림 대상, 승인 시 상태 변경 충돌.
화면: 관리 API와 OpenAPI 명세로 통합한다. UI 코드·화면 레이아웃은 이 저장소에 추가하지 않는다.

## 독립 검증용 참조 구현

초기 사용자 예시를 외부 서비스 없이 재현하도록 SQLAlchemy의 객체/관계 테이블과 문자 n-gram TF-IDF 검색을 추가했다. 기존 PostgreSQL을 사용할 수 있고 isolated SQLite 데모에서도 같은 업무 서비스를 실행한다. 이는 Neo4j 및 의미 임베딩 도입의 검증을 대신하지 않는다. 데이터·질문은 samples/warehouse_poc.json에서 버전 관리하고 모델 경계만 recorded-fixture로 교체한다.

재고 이벤트·초안은 DB 트랜잭션 및 revision/유일성으로 중복을 방지한다. 문서 검색·컨텍스트 전달 지표는 모델 오류와 구분해 저장한다. 실제 모델 평가와 기능 회귀·성능 반복을 분리하며 상세 계약은 [샘플 평가](SCENARIO_TESTING.md)를 따른다.
