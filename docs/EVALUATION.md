# 평가 계획

기준: [PRD](../PRD.md). 아래는 목표 테스트이며 실행 증거는 구현 상태 기록으로 남긴다.

## 첫 묶음: 기반·권한·Groq 경계

- 실제 API 로그인/로그아웃·만료·잘못된 비밀번호·비활성 사용자.
- 복수 Role 허용, 업무/범위 쌍 검사, 관리자 기능 접근 거절, 권한 회수 즉시 반영.
- 승인 요청의 중복/내용 충돌/반려/권한 회수와 영속 상태.
- Cloud 전송 거절이면 모델 호출 0회. 역할 사칭으로 권한 변화 없음.
- 구조화 의도 누락/잘못된 JSON/알 수 없는 업무/429/타임아웃/키 없음.
- Chat 재시도·다른 사용자 대화 접근·감사 기록의 비밀 제외.
- SQLite 격리 테스트와 실제 PostgreSQL 통합 검증 구분.
- 실제 Groq는 안전한 키·도메인 설정 후 합성 질문으로 확인. 키가 없으면 대역 검증을 실제 호출 성공으로 기록하지 않음.

## 후속 PoC 평가

대표 규정 질문 7개 중 5개 이상 핵심 사실·출처 정확. 관계 질의 2개 이상 포함.
정보 부족/권한 거절/근거 충돌 각 1개에서 안전하게 처리.
원천 레코드/관계 각 10개 고정 표본 중 8개 이상 일치.
PDF/Excel/HWP 각 대표 파일의 추출·검색·출처 확인.
재고 부족 → 관계 탐색 → 내부 알림 → 승인 → 초안 1개 실제 실행.
동일 적재/이벤트/승인 재처리로 중복 없음.
모델 설정 적용·감사·Hit·소요 시간 확인.

## 결과 기록

명령, 현재 커밋, 데이터/모델/프롬프트 버전, 통과/실패/skip/미실행, 실패 원인과 제약을 기록한다. 초기 성능·반자동 채택률은 측정만 한다. 실제 SAP/모델 미사용을 분명히 표시하며 PoC 전체 통과는 모든 필수 기준 검사 후에만 선언한다.
