# 개발 상태 — 첫 개발 묶음

검증일: 2026-10-08. 문서 선행 커밋: `d3c665e`. 실제 사용자가 승인한 공통 플랫폼 요구사항 및 Groq 전환을 반영한 뒤 구현을 시작했다.

## 구현됨

- Python 3.12·FastAPI·잠긴 uv 의존성·Alembic 초기 스키마.
- PostgreSQL + pgvector Docker 환경과 생성된 비밀을 Git에 넣지 않는 시작 절차.
- Argon2id 비밀번호·opaque bearer 세션 해시·로그아웃·만료·비활성화.
- 사용자/복수 Role 관리, 업무/범위 쌍 권한, 현재 권한 회수, 마지막 Admin 제거 차단.
- 발주 제안 승인 요청·승인/반려 상태·사용자별 중복방지 키·내용 충돌·감사 이력.
- Groq 구조화 의도 어댑터, LangGraph 해석/권한 노드, 대화 소유권·원문 맥락·동시 요청 중복 방지.
- 명시적 Cloud 전송 허용, 모델 오류 코드, 감사 최소 정보·시간, 비밀 제외 모델 설정 조회.

승인 상태 관리는 구현했지만 승인 후 실제 업무 실행은 아직 연결하지 않았다. Chat의 지원 업무는 의도·권한 확인만 하고 `not_available`로 응답한다. 외부 추적은 비활성화하며 CoT 원문은 저장하지 않는다.

## 검증 증거

- 격리 SQLite/API/모델 경계 테스트: 29개 통과.
- 실제 PostgreSQL 통합: 4개 통과. 초기 마이그레이션 재실행·pgvector 연산·서버 재생성 후 영속성·동시 승인 요청·동시 Chat·충돌 결정 감사 검사.
- 실제 HTTP smoke: 로그인·관리 권한 경계·승인 중복 방지·키 없음 처리 통과.
- 실제 API 프로세스의 live/ready/OpenAPI 요청: HTTP 200.
- Ruff lint/format, mypy strict, Alembic 모델/스키마 일치 검사 통과.
- Groq 인증 없는 models 요청: HTTP 401. 네트워크 도달은 확인했지만 계정 인증·모델 생성은 검증하지 않았다.

테스트 모델은 명시적 대역이며 실제 LLM 성능으로 집계하지 않는다. 실제 기업 데이터·SAP 연결은 사용하지 않았다. 입력 의미 파악 정확도와 최종 답변 품질은 실제 모델 평가 전까지 미검증이다.
