# 개발 상태 — 샘플 시나리오와 독립 평가

검증일: 2026-10-08. 기존 기반 구현 커밋은 e899775다. 샘플과 실패 테스트를 먼저 추가해 실패를 확인한 뒤 업무 로직과 독립 평가기를 연결했다.

## 구현 범위

기존 인증·복수 Role·범위 권한·승인 상태·감사·Groq 해석 기반에 다음을 추가했다.

- 버전 있는 합성 데이터, isolated demo DB, 생성된 로컬 자격증명과 관리/회계/현장/재고 계정.
- 온톨로지 정의·버전 저장, 관계 유형 검증, SQL 속성 그래프 적재·범위별 탐색과 원천 추적.
- 최신 재고·미입고 수량·발주 규칙 조회, 확인된 출고 이벤트의 트랜잭션 처리·중복 방지·내부 알림.
- 텍스트 문서 Chunk, 접근 권한 필터, 문자 n-gram TF-IDF 벡터 검색, 출처 및 검색/컨텍스트/인용 지표.
- Groq 근거 답변 계약, 허위 출처 검사, 문서별 Cloud 전송 허용 및 현재 권한 재확인.
- 발주 제안 → 승인 → 원천 revision/권한 재확인 → 초안 생성, 미입고 수량 반영과 중복 방지. 실제 ERP 등록은 안 함.
- 고정 응답 offline 모드, 실제 Groq 평가 모드, ASGI/실제 HTTP 두 전송 방식의 전체 시나리오 평가.
- 워밍업 제외·새 DB 반복·실패 구분·단계별 p50/p95·실제 모델 호출 시도 수·JSON 보고서.

## 검증 증거

- SQLite/API/모델 경계/업무/평가 테스트 44개 통과.
- 실제 PostgreSQL 통합 8개 통과: 마이그레이션·pgvector·재생성 후 영속성·동시 요청·완전한 업무 흐름·중복 이벤트/초안·동시 100개 출고의 이중 차감 방지.
- offline ASGI 전체 흐름 5회 통과, 규정 질문 매회 7/7 근거 일치. 최초 측정 전체 흐름 p50 약 180ms, p95 약 314ms.
- offline 실제 HTTP 전체 흐름 3회 통과. 최초 측정 p50 약 1.13초, p95 약 1.16초. 생성/적재/로그인/워밍업 제외한 로컬 참고값이며 운영 SLA 아님.
- 재실행 seed가 기존 상태·비밀번호를 보존함을 확인. 데모 ready/OpenAPI HTTP 200 및 CLI 권한 거절·규정 출처 확인.
- Ruff·mypy strict·Alembic 스키마 일치 검증.

측정 JSON은 Git에서 제외된 .local/reports에 생성한다. 데이터 버전과 실행 커밋·dirty 상태를 포함하며 재측정 결과가 달라질 수 있다. 실제 Groq 키가 주입되지 않아 Groq 생성·한국어 정확도·속도는 미검증이다. offline은 대역이고 실제 LLM 성능으로 집계하지 않는다.
